# Accessibility Implementation Review

- [ ] Native HTML provides the primary semantics.
- [ ] ARIA is used only where needed and does not contradict native behavior.
- [ ] Key controls expose the intended role, name, state, value, and relationships.
- [ ] Keyboard entry, operation, reverse navigation, Escape/cancel, and focus restoration work.
- [ ] Focus remains visibly unobscured by top bars, bottom navigation, sheets, or dialogs.
- [ ] Modal background is unavailable while the modal remains reachable and correctly exposed.
- [ ] Forms use visible labels and recoverable error behavior.
- [ ] Recoverable save failures preserve entered values.
- [ ] Primary navigation remains ordinary links unless a true application-menu contract exists.
- [ ] Composite widgets follow one complete interaction pattern without role mixing.
- [ ] Long text, zoom/reflow, reduced motion, target size, and gesture alternatives are implemented where relevant.
- [ ] Status meaning does not depend on color alone.
- [ ] AI/external action approval and execution states remain semantically distinguishable.
